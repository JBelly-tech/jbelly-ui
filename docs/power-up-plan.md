# jbelly-ui — power-up plan (handoff for an agent session)

Goal: make this skill the strongest **agent-neutral** UI skill on skills.sh —
works in any agent (Claude Code, Codex, Cursor, Gemini CLI, Copilot, Kimi…),
with any model, and is grounded in what people actually rate as good design.

Work phase by phase. Each phase has an exit check. Do not start the next phase
until the check passes. Commit after each phase. Ask the owner only the
questions in "Owner decisions" — everything else is answered here or in the repo.

---

## Phase 0 — Clean for publishing (blocker)

1. **Provenance leak.** Two tracked files under `comparison/iteration-2-complex-console/metrics/`
   carry a vendor template's name in their filename, and ~5 tracked files under
   `comparison/` mention it in content. The name is also in git history.
   Rename to `reference-template`, scrub content, then publish from a **fresh
   repo with a squashed first commit** (simpler and safer than history rewriting).
   Check: `git grep -i <vendor>` and `git log --all --name-only | grep -i <vendor>` both empty.
2. **Lean install.** `npx skills add` copies the skill folder. Move the skill into
   `skills/jbelly-ui/` (SKILL.md, references/, scripts/, assets/) and keep
   `comparison/`, screenshots and evals at repo root, outside that folder.
   Check: installed folder size < 1 MB.
3. **Spec compliance** (https://agentskills.io/specification): `name` matches the
   folder, lowercase-hyphen; `description` ≤ 1024 chars; add `license: MIT`;
   SKILL.md < 500 lines and < ~5000 tokens; references one level deep.
   Check: `skills-ref validate skills/jbelly-ui` passes
   (https://github.com/agentskills/agentskills/tree/main/skills-ref).

## Phase 1 — Agent-neutral and stack-neutral

4. **No agent-specific wording.** Replace tool names (Read, Bash, Agent…) and
   `~/.claude` paths with neutral verbs: "open `references/x.md`", "run `scripts/y`".
   README gives install paths for several agents, not one.
5. **Cross-platform scripts.** `.ps1` scripts do not run on most macOS/Linux
   setups. Port `lint-tokens`, `new-screen`, `verify-page` to Node (every
   skills.sh user already has `npx`) or Python. Each prints `--help` and clear
   errors. Delete one-off `_*.py` migration scripts from the shipped folder.
6. **Stack-neutral output.** Tokens ship as CSS variables **and** a DTCG JSON file
   (https://www.designtokens.org/). Recipes map to plain HTML/CSS, Tailwind and
   React in one table, so the agent picks the project's stack instead of forcing one.
7. **Cross-agent smoke test.** Install locally (`npx skills add ./`) into at least
   three agents and run the same brief.
   Check: all three trigger the skill and produce a page that passes Phase 3 checks.

### Reach every popular AI coding / web-building tool (owner requirement, 2026-09-17)

The skill must work wherever people build websites with AI, not only where
`SKILL.md` loads. One source, three delivery tiers — **generated by a script, never
hand-copied**, so the copies cannot drift.

7a. **Tier 1 — native Agent Skills (install as-is).** Listed as adopters on
    https://agentskills.io (checked 2026-09-17): Claude Code, Claude.ai,
    ChatGPT & Codex, Cursor, GitHub Copilot / VS Code, Gemini CLI, Kiro, TRAE,
    Roo Code, OpenCode, Junie, Amp, Goose, Mistral Vibe, Deep Code (DeepSeek),
    OpenHands, Factory. README gives the install path for each.
7b. **Tier 2 — tools that read a rules/knowledge file, not skills.**
    Lovable reads root `AGENTS.md` and a Knowledge box
    (https://docs.lovable.dev/features/knowledge). Check v0, Bolt, Replit and
    Windsurf in their own docs before claiming support — do not assume.
    Ship `dist/AGENTS.md`: the mandatory steps + exact tokens + anti-patterns,
    short enough to be read on every request.
7c. **Tier 3 — chat-only (ChatGPT web, Gemini app, Kimi, DeepSeek chat, Custom
    GPT, Gemini Gem, Claude Project).** No files, no scripts. Ship
    `dist/jbelly-ui-prompt.md`: one paste-in file, self-contained, under ~8K tokens.
7d. **Works without tools.** Every script step in SKILL.md has a manual fallback:
    "if you cannot run scripts, apply this checklist by hand". Steps are numbered,
    values are exact — weaker models follow numbers, not taste words.
7e. **Build script.** `scripts/build-dist` produces 7b and 7c from SKILL.md +
    references, and fails if either exceeds its size limit or is older than its sources.
   Check: one command builds all tiers; the Tier 3 file, pasted into a chat-only
   tool, produces a page that passes the Phase 3 deterministic checks.

## Phase 2 — Ground taste in evidence of what people like

Extract **patterns and principles only** — never copy code, CSS, icons or images.

8. **Human preference data (blind votes).**
   - Design Arena — https://www.designarena.ai — crowdsourced head-to-head votes on
     AI-generated UI, ranked with Bradley-Terry. Study the winning vs losing
     outputs; write down recurring traits.
   - LMArena WebDev — https://web.lmarena.ai — same idea for generated web apps.
9. **Real products people use and rate.**
   - Mobbin https://mobbin.com, Page Flows https://pageflows.com — real app screens and flows.
   - Awwwards https://www.awwwards.com (jury-scored), Godly https://godly.website,
     Land-book https://land-book.com, Refero https://refero.design — curated sites.
10. **Research-backed UX rules** — every rule in the skill should trace to one.
    - Nielsen Norman Group https://www.nngroup.com/articles/
    - Baymard Institute https://baymard.com/research (checkout, forms, e-commerce)
    - Laws of UX https://lawsofux.com
    - WCAG 2.2 https://www.w3.org/TR/WCAG22/ and APCA contrast https://apcacontrast.com
11. **Mature design systems** (for spacing, density, states, tone):
    Material 3 https://m3.material.io, Apple HIG https://developer.apple.com/design/human-interface-guidelines,
    Fluent 2 https://fluent2.microsoft.design, GOV.UK https://design-system.service.gov.uk
    (user-tested forms), Carbon https://carbondesignsystem.com,
    Radix Colors https://www.radix-ui.com/colors.
12. **Beat the competition, cheaper.** Read the source of the top UI skills on
    https://skills.sh (e.g. `anthropics/skills` frontend-design,
    `vercel-labs/agent-skills` web-design-guidelines, ui-ux-pro-max,
    design-taste-frontend). List what each does that this skill lacks, and what
    each costs in tokens. Adopt the gaps; never adopt subagent fan-out or
    mandatory re-check loops.
    **Known edge (checked 2026-09-17):** ui-ux-pro-max treats "dashboard" as a
    style row, a palette and a `--density` flag. It has no build recipe for an
    admin/dashboard screen (shell, sidebar, data table, filters, bulk actions,
    empty/loading/error states). jbelly-ui has one. Lead with this in the README,
    and give dashboard/admin briefs extra weight in Phase 3 to prove it.
13. **Anti-slop list.** Write `references/anti-patterns.md`: the tells of default AI
    UI (purple-blue gradients, one font everywhere, centered hero + 3 cards,
    emoji as icons, glass on everything, fake metrics, lorem ipsum, no empty /
    loading / error states). Each item: why it fails + what to do instead.
    Check: every new rule in the skill has a source link in the commit message or a reference file.

## Phase 3 — Measure (the eval harness)

### Minimum setup — test without owning every tool (2026-09-17)

What is tested is **model + instructions**, not each tool's UI. A chat tool sees
exactly what an API call with the Tier 3 file sees, so most of the matrix needs
one API key, not ten subscriptions.

- **A. Free, local:** deterministic checks (Playwright + axe-core) on saved HTML.
  Reuse the `comparison/` folder layout (outputs, grading, timing).
- **B. One key for all models:** OpenRouter, OpenAI-compatible,
  base URL `https://openrouter.ai/api/v1` — one key reaches Claude, GPT, Gemini,
  Kimi, DeepSeek, Qwen (https://openrouter.ai/docs/quickstart). Script
  `evals/run-matrix` loops briefs × models, sends the Tier 3 file + brief, saves
  HTML and token usage. Key in env var `OPENROUTER_API_KEY`, never committed.
  Set a hard spend limit on the key. Read prices from the model page at run
  time — never from memory.
- **C. Real agents, only those already owned:** Tier 1 in Claude Code, plus a
  second agent only if the owner already has it. README states which agents were
  tested and which are format-compatible only.
- **D. Small model, optional, free:** a local model via Ollama or LM Studio.
- **E. Humans:** a local blind A/B page; raters see screenshots of neutral sample
  pages only.
- **Start small:** 5 briefs × 4 models × (with / without skill) = 40 pages. Grow
  only after this run works end to end.
- **Do not plan on free tiers without checking.** Example: the Gemini CLI free
  personal login was reported ended in June 2026.

14. **Brief set.** 12–15 fixed briefs in `evals/briefs/`: dashboard, landing,
    pricing, sign-up form, data table, settings, e-commerce product page, mobile
    screen, dark mode, **RTL Arabic** page, dense admin, empty-state-heavy app.
    RTL is a differentiator — most UI skills break on it.
15. **Deterministic checks (no model):** axe-core accessibility, contrast, token
    lint (no hard-coded colours/sizes), Playwright screenshots at 375 / 768 / 1440,
    horizontal-overflow detection, Lighthouse score. One command runs them all
    and writes JSON.
16. **Blind human rating.** Pairwise A/B pages (no labels): skill vs no-skill vs
    2 competitor skills. Owner + 3–5 people vote. Report win rate
    (Bradley-Terry if > 50 votes). A model judge is a tie-breaker only.
17. **Across models.** Pick the models at test time from the current top of the
    Design Arena and LMArena WebDev leaderboards — never from memory. Cover at
    least: Claude, GPT, Gemini, one open model (Kimi / DeepSeek / Qwen), and one
    small/cheap model. Run Tier 1 in two agents and Tier 3 in one chat tool.
    "Works on any popular model" must be a measured table, not a claim.
    Log tokens per page into `COST.md`.
18. **Iterate one change at a time.** Keep a change only if win rate rises and
    tokens do not. The `skill-creator` skill (anthropics/skills) supports this loop.
    Check: a results table exists showing win rate + tokens per model, before and after.

## Phase 4 — Trigger precision and cost

19. Write 20 prompts that **should** trigger and 20 that **should not**
    (e.g. "fix this SQL query"). Tune `description` until both pass ≥ 90 %.
    Shorter description = cheaper for every user on every request.
20. SKILL.md holds only the router + the mandatory steps; everything else lives
    in `references/` and is opened by task type (`quick-card.md` first).

## Phase 5 — Publish and grow

21. Public GitHub repo, MIT. README top: one-line pitch, before/after screenshots,
    install command `npx skills add <owner>/<repo>`, supported agents, win-rate table.
22. skills.sh has no submit step: its leaderboard is built from anonymous install
    telemetry of the `skills` CLI (https://skills.sh/docs). After the first
    installs, confirm it appears with `npx skills find jbelly`.
23. Semver tags + CHANGELOG per release. Issue template "UI came out bad" asking
    for brief + screenshot + agent + model — every report becomes a new eval brief.
